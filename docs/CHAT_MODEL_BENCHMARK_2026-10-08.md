# Влияет ли смена модели на скорость ответов Васи — 8 октября 2026

## Что измерено

Локальный Mac с 16 ГБ RAM и Ollama. Использованы два синтетических русскоязычных вопроса с промптом обычного чата из `services/chat_service.py` и один синтетический фрагмент заметки с промптом из `services/grounded_knowledge_answer_service.py`. Личные документы и запросы не передавались моделям. Для чата: потоковый ответ, `temperature=0.25`, `num_predict=120`; для заметки: один JSON ответ, `temperature=0`, `num_predict=320`. В таблице один прогон на модель, `llama3` измерена дважды. Длительности и число токенов взяты из ответа Ollama, время первого токена — на стороне клиента.

| Модель | Первый ответ чата | Тёплый ответ чата | Первый токен тёплого ответа | Ответ по заметке | Скорость генерации |
| --- | ---: | ---: | ---: | ---: | ---: |
| `llama3:latest` | 17,7–20,3 с | 4,4–9,1 с | 1,8–2,1 с | 3,8–4,0 с, JSON принят | 17–18 токенов/с |
| `qwen2.5:3b` | 23,5 с | 2,4 с | 1,0 с | 2,9 с, JSON принят | 29–35 токенов/с |
| `gemma3:4b` | 17,5 с | 2,0 с | 1,1 с | 2,9 с, JSON отклонён | 27–29 токенов/с |

Холодный и тёплый вопросы различались, поэтому их длительности нельзя сравнивать между собой. В каждом столбце модели получали одинаковый вопрос, но ответы содержали от 27 до 120 токенов; общая длительность зависит и от длины ответа. `llama3` дважды и `qwen2.5:3b` один раз достигли лимита 120 токенов на объяснении и оборвали предложение. Значения выше показывают направление возможного выигрыша, но не p95 и не качество на широком наборе вопросов.

## Совместимость с текущим продуктом

- Быстрые короткие реплики используют `OLLAMA_FAST_MODEL` (сейчас `llama3`); установка другой `OLLAMA_CHAT_MODEL` их не ускорит.
- Длинный чат и ответы по найденным заметкам используют `OLLAMA_CHAT_MODEL`. `qwen2.5:3b` на этом Mac генерировала примерно в 1,6–2 раза больше токенов в секунду, но её первый ответ оказался медленнее из-за 16,5 с загрузки модели.
- `gemma3:4b` обернула JSON ответа по заметке в Markdown блок. Реальный `answer_from_hits()` вернул `None` на корректной синтетической выдержке. Поэтому текущий путь ответов по документам с этой моделью не работает без адаптации формата или отдельного выбора модели.
- При проверке маршрутизатора на прежнем наборе из 13 синтетических запросов `qwen2.5:3b` верно определила 11, `llama3` — 12. Ошибки `qwen2.5:3b` затронули создание встречи и удаление задачи; менять на неё маршрутизатор нельзя без дополнительной защиты.
- С одновременно загруженными `llama3` и `qwen2.5:3b` команда `ollama ps` показывала 5,2 и 2,4 ГБ соответственно; свободная доля системной памяти Mac снизилась до 52%. Разделение моделей чата и маршрутизатора требует учитывать RAM и политику предварительного прогрева.

## Вывод

Другая модель может ускорить **длинный текстовый ответ** и появление первого слова после прогрева. Она не ускорит распознавание речи, Silero, поиск документов или короткие ответы, которые используют модель маршрутизатора. Сейчас `llama3` оставлена основной моделью: этот маленький тест не подтверждает безопасную замену для всех путей Васи. `qwen2.5:3b` — кандидат для отдельного пробного режима чата после более широкого теста русских ответов, цитирования и памяти. На домашнем Ryzen 5 2400G без дискретной GPU эти времена не переносимы; замер нужно повторить на сервере.

Пробные модели удалены из локального Ollama после проверки, чтобы `OLLAMA_CHAT_MODEL=auto` снова выбирал прежнюю модель. Размеры и API поля можно сверить с [каталогом Qwen2.5](https://ollama.com/library/qwen2.5), [каталогом Gemma 3](https://ollama.com/library/gemma3) и [документацией Ollama Generate API](https://docs.ollama.com/api/generate).
